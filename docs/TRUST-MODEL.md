# TRUST-MODEL — siapa dipercaya untuk apa

Dokumen ringkas untuk pelapor keamanan dan implementer. Sumber normatif tetap [`SPEC.md`](../SPEC.md): §14 (approval, sandbox, redaksi), §11.11 (model konkurensi & persistence), §22.1 baris GAP-SEC-28. Bila berbeda, SPEC berlaku.

## 1. Batas keamanan vs heuristik

| Jenis | Isi | Bug di sini |
|---|---|---|
| **Batas** (boundary) | Sandbox path SPEC §14.2 **hanya** untuk tool kode (`read_file`, `grep`, `glob`, tulis/edit) di semua mode, termasuk symlink yang ter-resolve keluar root (verdict `outside_root`) (ADR-079); approval + preview SPEC §14.1 dan P26 = kontrol untuk shell dan `execute_code`: shell **bukan** boundary path, setiap perintah shell butuh approval eksplisit kecuali cocok persis `shell_allow` atau jalur headless `damnbot run --unsafe-auto-shell` yang terdokumentasi (ADR-079), dan setiap `execute_code` butuh approval eksplisit kecuali `language` ada di `exec.code_auto_languages` dengan syarat SPEC §14.1 (ADR-089); gerbang DLP egress `internal/netx` (P29), **hanya** untuk egress tool built-in lewat `internal/netx` (ADR-069); akses gateway P25 (allowlist, owner-only untuk aksi berbahaya); guard sesi + fencing DB SPEC §11.10–§11.11; verifikasi tanda tangan update/indeks hub (ed25519) | vulnerability, in-scope |
| **Heuristik** (defense-in-depth) | Classifier shell: hanya label risiko untuk preview/bentuk prompt dan penolakan headless, plus `denied_path` best-effort; tidak pernah menghasilkan auto, ketiadaan label tidak menjamin apa pun (isolasi kuat = backend container) (ADR-079); egress subprocess (shell, execute_code, hook, MCP stdio, LSP) = approval, tidak melewati DLP/SSRF `netx` (ADR-069); threat scan skill/memori, redaksi berbasis pola, taint `<untrusted>`, smart approval | dilaporkan sebagai kelemahan; bukan batas |

Vulnerability (ADR-079 butir 8, diperluas ADR-089 butir 1): (a) perintah shell **atau kode `execute_code`** yang berjalan tanpa approval eksplisit di luar jalur auto terdokumentasi (`shell_allow` argv-persis, `--unsafe-auto-shell`, `exec.code_auto_languages` dengan syarat SPEC §14.1); (b) tool kode yang mengakses luar root/`deny_paths` tanpa verdict yang benar; (c) egress tool built-in yang lolos DLP `netx`. Efek perintah yang sudah di-approve user (termasuk filter git, rekursi symlink) dan TOCTOU antara preview dan eksekusi = sisa risiko (§3).

## 2. Aktor

| Aktor | Dipercaya untuk | Tidak dipercaya untuk | Penegakan |
|---|---|---|---|
| **User OS lokal** (akun yang menjalankan damnbot) | Semua: memegang file data, kunci, config | — | Di luar model: akses tulis ke `<data_dir>` setara akses penuh (dapat mengubah DB, trigger, binary) |
| **Owner** (identitas yang di-pair sebagai owner, P25) | Approval semua kelas, termasuk kelas berbahaya dan P26; menjawab approval lintas kanal; `edit` jarak jauh (selalu menjadi permintaan + preview baru) | Melewati P26 tanpa preview; menyetujui kelas P26 (`irreversible`, `monetary`, `delegated_agent_bypass`) selain lewat kanal interaktif yang merender preview SPEC §18.2: TUI, ACP (`session/request_permission` dengan konten preview), web UI, gateway owner (inline keyboard + preview); bukan `mcp_serve`, bukan headless (headless produksi tanpa approver → P26 `denied`) (ADR-076, ADR-084) | SPEC §14.1, §11.11.10 |
| **User gateway** (identitas allowlisted, role `user`) | Mengobrol, tool non-berbahaya di sesi/memori miliknya, kuota P25 | Aksi berbahaya, approval kelas berbahaya, sesi/memori identitas lain; file di luar workspace-nya (termasuk cwd owner/`serve`) dan blob sesi identitas lain; shell tanpa backend container (ADR-076) | P25, isolasi scope memori; root sandbox = **hanya** workspace identitas: kolom `gateway_identities.workspace` bila non-NULL, selain itu default turunan `<data_dir>/gw-workspaces/<identity_hash>` (dibuat saat pairing, root tidak pernah kosong); `[gateway.users.<id>] workspace` menimpa dan ditulis ke kolom saat pairing/startup (ADR-084); shell hanya lewat backend container (ADR-076); `TestGatewayUserRootIsolation`, `TestGatewayUserBlobScope` (F4) |
| **Identitas tidak dikenal / `weak`** | Tidak ada (0 tool call, 0 LLM call) | Semua | P25, SEC-10 |
| **Kanal** (TUI, ACP client, web UI, platform chat, klien `mcp serve`) | Menyampaikan input dan keputusan dari identitas yang terautentikasi di kanal itu | Mengklaim identitas lain; menjawab approval di luar `channels[]` (kecuali owner) | Auth per kanal (§13), `request_id` + `preview_sha` (§11.11.10) |
| **Klien `mcp serve`** | Scope token: `read`, `send` (allowlist target + approval), `approve` (approve/deny saja) | `edit` argumen, sesi identitas lain; menjawab approval atas permintaan ber-`origin = mcp_serve` (field `origin` ∈ {`tui`, `acp`, `web`, `gateway`, `headless`, `mcp_serve`} di payload JSON `approval_request`); menjawab kelas P26 dari sumber mana pun (ADR-076, ADR-084) | Token terikat profil + identitas (SEC-21), CHECK DB; tabel otoritas §11.11.10: sumber `mcp_serve` hanya menjawab `origin ≠ mcp_serve` dan kelas non-P26; `TestMCPServeCannotSelfApprove` (F5) (ADR-084) |
| **Server MCP** (tool pihak ketiga) | Schema + hasil tool sebagai **data** | Instruksi di deskripsi/hasil; efek tanpa approval (default `non_idempotent`, `untrusted`) | Pin tool (SEC-04), taint, approval §14.1 |
| **Skill** (bawaan, hub, buatan agent) | Instruksi kerja setelah lolos karantina/review | Melewati approval; skill hub tanpa tanda tangan | Karantina, threat scan, tanda tangan indeks (SEC-20) |
| **Model (output LLM)** | Usulan tool call dan teks | Apa pun tanpa validasi: argumen divalidasi schema (P3), aksi melewati approval/sandbox | P3–P5, §14 |
| **Konten eksternal** (web, file di luar workspace, hasil tool, email, pesan platform) | Data | Instruksi (`<untrusted>`, taint) | Taint lengket per turn → approval naik (ADR-070) |
| **Konten repo/workspace** (AGENTS.md, context file, file kerja, config repo/`git`, skrip build/test) (ADR-069) | Data dan, bila workspace **trusted**, aturan proyek (AGENTS.md) | Workspace untrusted: instruksi (AGENTS.md/context file dibungkus `<untrusted source="workspace">`), menjalankan kode workspace secara otomatis | Workspace trust per path kanonik (`security.trusted_workspaces`; prompt saat root dibuka interaktif; headless `run` untrusted kecuali terdaftar) (ADR-069). Untrusted: konten file men-taint turn, **setiap** output shell dibungkus `<untrusted source="workspace">` dan men-taint turn, jalur auto `shell_allow` (termasuk verify) dan `--unsafe-auto-shell` mati, hook proyek tidak berjalan (F3), LSP/build script/proc-macro/plugin `node_modules`/Gradle/Maven tidak pernah dimulai otomatis (diagnostik hanya go/ast + tree-sitter WASM; ADR-089) (ADR-069, ADR-079). Trusted pun tidak memberi auto shell selain `shell_allow` argv-persis (ADR-079) |
| **Proses damnbot lain** (TUI/ACP/`serve` milik user yang sama) | Menulis DB sesuai lease dan mode | Menulis sesi yang di-lease proses lain atau sedang dipurge | Fencing token + guard DB (§11.10–§11.11) |

## 3. Residu yang diakui (tidak dijamin)

| Residu | Dampak | Rujukan |
|---|---|---|
| Proses berhenti (SIGSTOP/debugger/hang) di dalam transaksi tulis | Penulisan semua proses tertahan; dilaporkan `db_write_stalled`, tidak dibunuh otomatis | SPEC §11.11.13 #37 |
| Time namespace berbeda pada kernel sama | Tidak didukung; liveness lease bisa salah, keselamatan tetap dijaga fencing | #40 |
| Id sesi di payload JSON bebas setelah purge | Purge menjamin rujukan terstruktur saja; payload bebas = anonimisasi best-effort | #48, I13 |
| Backup otomatis (`daily-*` 3, `premigrate-*` 2) dan arsip pengguna | Masih memuat data sesi yang di-purge sesudahnya sampai backup dirotasi/dihapus | SPEC §11.6 Backup/restore |
| Restore ke data dir lain (tanpa `purge.log`) | Purge yang terjadi setelah snapshot tidak dapat diterapkan ulang | SPEC §11.6 |
| `messages_send` tanpa `idempotency_key` di-retry klien | Dapat menghasilkan dua permintaan (masing-masing butuh approval) | #68 |
| macOS: turunan tool yang membuat session/process group baru (`setsid`) saat pemiliknya mati | Lolos dari SIGKILL pgid pengambil alih; Linux dan macOS menangkapnya lewat sweep marker saat start berikutnya (bukan `cgroup.kill`), Windows lewat Job Object | #74, ADR-105 butir 1 |
| Shell escape yang menghapus marker atau keluar dari pohon: `env -i … setsid …`, `sudo`/`setuid`, `systemd-run --user`, `at`/`cron`, WMI/schtasks | Tidak terjangkau pgid maupun sweep marker; proses jenis ini tidak dijamin mati saat call selesai. Proses yang tetap memegang PTY tidak lagi menahan call (master ditutup, read dibatalkan) | EX39-3, EX40-1, ADR-105 butir 8 |
| Pesan masuk antre (`gateway_inbound.payload`) | Isi tersimpan di DB sampai diproses (lalu dikosongkan); dicakup `storage.encrypt` | ADR-046 |
| Inbound dari platform yang tidak mengirim ulang event yang belum di-commit (push wajib-ack maupun tanpa ack) | Saat DB tidak bisa ditulis atau exit terencana, event masuk spool `run/inbound_spool/` (SPEC §11.11.7) dan tidak hilang. Platform ber-API riwayat memakai `gateway_cursors` untuk backfill sejak id terakhir yang ter-commit | ADR-052 AF-06 (`S084_SpoolDuringDrainBarrier`) |
| ≤ 1 LLM call atau ≤ 1 start tool basi per turn | Dari proses yang terhenti tepat setelah titik cek lease; hasil tidak ditulis | I4 |
| Efek perintah shell yang di-approve user (atau cocok `shell_allow`, atau berjalan lewat `--unsafe-auto-shell`) | Efek tersembunyi (eksekusi kode lewat config repo seperti filter `clean`/`smudge` git, rekursi lewat symlink keluar root, tulis, baca di luar root) tidak dijamin terdeteksi label classifier; label hanya membentuk preview; isolasi kuat hanya lewat backend container | ADR-079 butir 8 |
| Approval verdict `hardlinked_file` (tool kode) | File reguler dengan jumlah link > 1 di dalam root selalu butuh approval; setelah di-approve, `OpenApproved` membuka objek apa pun yang dinamai link itu (bisa file di dalam direktori deny atau cocok glob deny), kecuali objek pola deny literal yang ditolak lewat identitas. Hard link dibuat oleh perintah yang sebelumnya di-approve (shell, tar); preview approval menampilkan alasan `hardlinked_file` | ADR-097 butir 10, 12 |
| TOCTOU antara preview dan eksekusi shell | Filesystem, config repo, atau `PATH` dapat berubah antara preview yang di-approve dan eksekusi; preview tidak menjamin efek yang sama | ADR-079 butir 8 |
| `damnbot run --unsafe-auto-shell` (headless `--approval auto`) | Perintah berkelas `mutating` (dengan/tanpa `network`) pilihan model berjalan tanpa konfirmasi bila workspace trusted dan turn tidak tainted; `destructive`, `unknown`, P26, `privileged`, `denied_path` tetap `denied`; flag `outside_read` → `outside_workspace` (ADR-088 butir 2). "runs arbitrary shell commands chosen by the model without confirmation; use only in a disposable container" | ADR-079 butir 4 |
| Egress subprocess (shell, execute_code, hook, MCP stdio, LSP) | Tidak melewati gerbang DLP/SSRF `netx`; hanya approval (label `network`, output `<untrusted source="shell:network">` men-taint turn) | ADR-069 butir 5, ADR-079 butir 6 |
| Secret ref `exec.env` (`keychain:<id>`) yang disuntikkan hanya pada mode execve runner (tanpa interpreter) untuk argv0 ∈ `commands` | Program yang di-approve user dapat mentransformasi nilai (encode, tulis file, kirim jaringan) sehingga lolos redaksi pola/nilai; Damn-Bot tidak pernah menyuntikkannya ke konteks model, sesi shell, atau `bash -c` | ADR-081 butir 1, ADR-088 butir 4 |
| Eksekusi kode proyek oleh language server di workspace trusted yang tidak bisa dimatikan lewat setting server (build script/proc-macro dimatikan bila didukung, mis. rust-analyzer `cargo.buildScripts.enable=false`, `procMacro.enable=false`; tsserver tanpa plugin workspace) | LSP di workspace trusted dapat menjalankan kode proyek tanpa approval per aksi; workspace untrusted tidak pernah memulai LSP/build | ADR-089 butir 2 |
